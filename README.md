# Room Booking Service

## Стек технологий
* **Language:** Go 1.25
* **Database:** PostgreSQL 16

---

## Ключевые проектные решения

### 1. Ленивая генерация слотов
Слоты для бронирования не создаются заранее на определенный срок. 
Они генерируются динамически в момент первого запроса пользователя к списку слотов конкретной комнаты на конкретную дату.

Почему это эффективно:
* Storage Efficiency: Таблица `slots` не раздувается лишними записями.
* Performance: Легкие индексы и компактный Buffer Pool в PostgreSQL обеспечивают высокую скорость чтения.

### 2. Гарантии целостности данных
Для защиты от гонки данных при одновременной генерации слотов несколькими пользователями используется многоуровневая защита:

* Unique Constraint: В бд наложен составной индекс `UNIQUE (room_id, start_at)`.
* Атомарность: Генерация всей пачки слотов на день происходит внутри одной транзакции (уровень `Read Committed`).

В итоге база данных выступает финальным арбитром - даже при конкурентных запросах дублирование записей физически невозможно.

### 3. Инфраструктурное тестирование
E2E тесты запускаются в реальном окружении PostgreSQL благодаря testcontainers. Это гарантирует, что:

* SQL-миграции корректны и совместимы с кодом.
* Сложные запросы и ограничения работают так, как ожидается.
* Тесты изолированы и не требуют предварительно настроенной БД.

### 4. Безопасность и аутентификация
В системе реализована полноценная аутентификация на базе JWT(эндпоинты `/register` и `/login`):

* Stateless: Серверу не нужно хранить сессии в базе или оперативной памяти, 
что упрощает горизонтальное масштабирование сервиса.
* RBAC: Использование Middleware для гибкого разграничения прав доступа.
* Security: Пароли пользователей хранятся в хешированном виде с использованием алгоритма bcrypt.

### 5. Автоматизация и документация
Проект спроектирован для максимально быстрого погружения нового разработчика и удобства интеграции:

* Self-Documenting API: Полная интеграция со Swagger. 
Актуальная документация всегда доступна по эндпоинту `/swagger`.
* Standardized Workflow: Наличие Makefile унифицирует ключевые процессы разработки. 
Команды `make up` и `make seed` позволяют развернуть инфраструктуру и наполнить базу данными одной командой.

## Тестирование и покрытие

Запуск тестов производился через:
```bash
go test -coverpkg=./... -coverprofile=cp.out ./...
go tool cover -func=cp.out
```

Итоговое покрытие составило ~41%
