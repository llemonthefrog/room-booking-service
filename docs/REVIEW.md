# Ревью проекта

## Что исправлено

| Приоритет | Проблема | Исправление |
| --- | --- | --- |
| Высокий | При полностью занятом дне сервис снова вставлял слоты и получал ошибку уникальности. Конкурентная первая генерация тоже могла завершаться ошибкой. | Вставка пропускает существующие слоты, после неё сервис читает доступные слоты из БД. Занятые слоты не возвращаются как свободные. |
| Высокий | Проверка владельца отменённой брони выполнялась после раннего возврата. | Владелец проверяется до проверки статуса. Чужая бронь возвращает 403, включая уже отменённую. |
| Высокий | Уникальный индекс бронирований проверял `active`, приложение записывало `created`. | Миграция 000006 приводит старые статусы, значение по умолчанию и индекс к `created`, ограничивает допустимые статусы. |
| Средний | Ошибки подключения к БД выдавались за отсутствие комнаты или слота. Ошибка чтения расписания игнорировалась. | Сервисы передают исходные ошибки; обработчики используют `errors.Is`. |
| Средний | Репозиторий пользователей проверял `pq.Error`, хотя подключение использует pgx. | Проверяется `pgconn.PgError`: повторная регистрация возвращает 400, гонка создания расписания — 409. |
| Средний | Повторный `/dummyLogin` пытался повторно создать того же пользователя и падал. | После конфликта проверяется существующий пользователь с фиксированным ID и ожидаемой ролью. |
| Средний | JWT принимал другие HMAC-алгоритмы и токены без срока действия. | Разрешён HS256, обязательны срок действия, корректные UUID и роль. |
| Средний | Пустой пароль проходил регистрацию, слишком длинный пароль и неверные данные приводили к 500. | Добавлена проверка длины пароля и роли, ошибки ввода возвращают 400. |
| Средний | `PORT` игнорировался, отсутствовали таймауты сервера, `sql.Open` не проверял соединение. | Используется `PORT`, заданы таймауты и начальный `PingContext`. |
| Низкий | Небезопасное приведение контекста могло вызвать panic, большое значение страницы — переполнение offset. | Типизированные ключи, проверка наличия пользователя и переполнения. |
| Низкий | Swagger не был зарегистрирован, отсутствовала схема BearerAuth; `make seed` был сломан. | Подключена документация, добавлена схема авторизации, исправлены путь и столбцы SQL. |

## Роутинг

`chi` заменяет `http.ServeMux`. Адреса API и роли сохранены. Авторизованные маршруты объединены в группу, внутри неё отдельно объявлены маршруты администратора и пользователя. Самописный `Chain` удалён; добавлены стандартные middleware chi для ID запроса, журнала запросов и восстановления после panic.

Неизвестный GET теперь возвращает 404: раньше обработчик `GET /` в ServeMux принимал и неизвестные пути. Обработчики остаются обычными `http.Handler`, сервер — `http.Server`.

## Что осталось за рамками

- **Учебная авторизация.** `api.yaml` явно требует `/dummyLogin` и разрешает регистрацию администратора. Контракт сохранён. Перед публичным развёртыванием нужно убрать тестовый вход, запретить самостоятельное назначение admin и заменить демонстрационный JWT_SECRET в Compose.
- **Входные JSON-запросы.** Нет ограничения размера тела, проверки второго JSON-объекта и ограничения частоты попыток входа. Это следующий небольшой шаг перед публичным доступом.
- **Контракт комнаты.** Поля `description` и `capacity` принимаются DTO, но не сохраняются. Стоит отдельно согласовать поддержку этих полей; это потребует изменения модели и миграции.
- **Конкурентная отмена.** Последовательная повторная отмена идемпотентна. При двух одновременных отменах одной брони один запрос ещё может получить 404: транзакция обновляет только статус `created`.
- **Наблюдаемость.** Журнал запросов показывает статусы и время, но для диагностики сбоев БД стоит добавить логирование исходных ошибок с ID запроса.

## Миграция существующей базы

Миграция 000006 выполняется транзакционно и не удаляет бронирования. Если в старой базе уже есть несколько активных броней одного слота, новый индекс не создастся. Такие данные нужно проверить и исправить отдельно; автоматически выбирать бронь для удаления нельзя.

## Проверки

- `go test -short ./...`: unit-тесты сервисов и HTTP-маршрутов без Docker.
- `go test -race -count=1 -timeout=3m ./...`: также E2E на PostgreSQL 16 через testcontainers.
- E2E проверяет конкурентное создание расписания и слотов, единственную успешную бронь, ограничение уникальности напрямую в БД, полностью занятый день, отмену владельцем и повторное бронирование.
- `go vet ./...` и `git diff --check`.
